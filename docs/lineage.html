Data Lineage

Data model, pipeline stages, and source-to-output file mappings.

data model

All processed data conforms to a canonical five-field schema. Every metric row across all sources uses the same structure, enabling uniform querying and presentation.

entity string Institution name (e.g. "ANZ", "Kiwibank"). Standalone bank or group entity as published by RBNZ.
metric string Canonical metric name as defined in glossary.md. Must match exactly — no synonyms or abbreviations.
value number | null Numeric value as published in the source. Not rounded, normalised, or imputed. Null when the source has no data for this entity/metric/period combination.
period string Quarter identifier in YYYY-QN format (e.g. "2024-Q3"). Derived from quarter-end date in the source file.
source string Data source identifier (e.g. "RBNZ", "ANZ-GDS"). Links the row back to its originating file for audit purposes.

Additionally, processed rows include an entity_type field ("standalone" or "group") used by the frontend to distinguish bank-level from group-level data.

pipeline stages

The pipeline has three stages with strict separation of concerns.

1
Fetch (Ingestion)
Downloads raw source files from public URLs. No transformation is performed. Output is committed to data/raw/.
Script: scripts/fetch_data.py
Workflow: .github/workflows/fetch-data.yml — runs monthly on the 1st and on manual dispatch.
2
Process (Transformation)
Parses raw XLSX, maps series IDs to canonical metric names via config/metrics.yaml, normalises period strings, and writes canonical CSV rows to data/processed/. Also produces docs/data/processed/metrics.json for frontend consumption.
Module: src/processing/
Workflow: .github/workflows/process-data.yml
3
Publish (Presentation)
The docs/ directory is published via GitHub Pages. No build step — all files are static HTML, CSS, and JS. The frontend fetches data/processed/metrics.json at runtime and computes derived metrics client-side.

disclosure pipeline

In addition to the RBNZ XLSX pipeline, this repository includes a supplementary disclosure pipeline that extracts financial metrics from bank General Disclosure Statements (GDS) — quarterly PDF reports published by each bank on their own website.

The disclosure pipeline follows the same canonical schema and separation-of-concerns as the main pipeline: PDFs are fetched to data/raw/disclosures/, parsed in src/processing/, and output to docs/data/processed/disclosure_metrics.json. A metadata index of available disclosure PDFs is written to docs/data/processed/disclosures.json and used by the Disclosures page.

configuration files

File Purpose
config/metrics.yaml Maps RBNZ series IDs (e.g. DBB.QIB12) to canonical metric names. Only mapped series are included in processed output.
config/capital_requirements.yaml RBNZ 2019 capital reform phase-in schedule. CET1 minimums by bank type (D-SIB vs non-D-SIB) and year 2023–2028. Used to compute Capital Headroom.
glossary.md Canonical metric name registry. Every metric name in code, config, or data must appear verbatim here.
